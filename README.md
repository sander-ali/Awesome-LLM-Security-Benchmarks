## About

Evaluating whether an LLM is *secure* or not merely *capable* has produced a sprawling literature of benchmarks, each probing a different failure mode: a model that caves to a jailbreak, one that leaks a backdoor planted at training time, an agent that obeys an instruction hidden in a retrieved web page, a chatbot that stereotypes a demographic group, or a vision-language model that is smuggled harmful content inside an innocuous-looking image.

This repository collects that landscape in one place. It is a **reference catalog**, not a leaderboard: the goal is to help researchers, red teamers, and builders quickly find the right evaluation for the risk they care about, follow it back to the primary source, and reuse a clean, structured dataset (JSON/CSV/YAML) in their own tooling.

**Design principles**

- **Faithful, not invented.** Long-form descriptions, security-type labels, names, categories, and every hyperlink are copied verbatim from the source workbook; the raw file is committed under [`data/source/`](data/source/) for anyone to diff against. See [Provenance & Data Notes](#provenance--data-notes).
- **One source of truth.** [`data/benchmarks.json`](data/benchmarks.json) drives the README, the docs pages, and the CSV/YAML exports via [`scripts/build.py`](scripts/build.py).
- **Reproducible & dependency-free.** Both scripts use only the Python standard library (an `.xlsx` is just a ZIP of XML, so no spreadsheet library is required).
- **Primary sources first.** Each entry links to the official site/code and the paper.

## Benchmarks by Category

Full detail for every benchmark — venue, links, the security type(s) it targets, and a summary of what it measures and finds.

<a id="cat-adversarial-and-jailbreak"></a>
### 1. 🎯 Adversarial & Jailbreak

*5 entries · [open category page →](docs/adversarial-and-jailbreak.md)*

These benchmarks stress-test a model's refusal behavior under deliberate attack. They range from standardized red-teaming harnesses and shared behavior suites (HarmBench, JailbreakBench), to the gradient-based adversarial-suffix lineage that began with the GCG attack (AdvBench), to evaluators that judge whether a 'successful' jailbreak actually produced harmful, useful-to-an-attacker output rather than an *empty* jailbreak (StrongREJECT), to large in-the-wild collections of role-play prompts (Do Anything Now). Use them to measure attack success rate, refusal robustness, and the quality of your safety judging.

**In this category:** [HarmBench](#bm-1) · [JailbreakBench](#bm-2) · [AdvBench](#bm-3) · [StrongREJECT](#bm-4) · [Do Anything Now (DAN) Jailbreak Prompts](#bm-5)

<a id="bm-1"></a>
#### 1. HarmBench

*2024 · Mazeika et al.*

- **Website / Code:** [harmbench.org](https://harmbench.org/)
- **Paper:** [arXiv 2402.04249](https://arxiv.org/abs/2402.04249)
- **Security Type Targeted:** Adversarial robustness; jailbreak attacks; automated red teaming

Standardized evaluation framework for automated red teaming and robust refusal. Provides shared behavior test suites, canonical attack/defense taxonomies and leaderboards, plus a large-scale comparison of 18 red-teaming methods against 33 target LLMs and defenses; also introduces an efficient adversarial-training defense.

[↑ Back to top](#top)

<a id="bm-2"></a>
#### 2. JailbreakBench

*2024 · NeurIPS D&B Track · Chao et al.*

- **Website / Code:** [jailbreakbench.github.io](https://jailbreakbench.github.io/)
- **Paper:** [arXiv 2404.01318](https://arxiv.org/abs/2404.01318)
- **Security Type Targeted:** Jailbreak attacks; safety alignment robustness

Open robustness benchmark that standardizes jailbreak evaluation: 200 curated benign/misuse behaviors (JBB-Behaviors, referenced to OpenAI usage policies and sourced in part from TDC, HarmBench and AdvBench), a public artifacts repository of jailbreak submissions, and a live leaderboard for attacks and defenses.

[↑ Back to top](#top)

<a id="bm-3"></a>
#### 3. AdvBench

*2023 · Zou et al. (GCG project)*

- **Website / Code:** [llm-attacks.org](https://llm-attacks.org/)
- **Paper:** [arXiv 2307.15043](https://arxiv.org/abs/2307.15043)
- **Security Type Targeted:** Adversarial suffix attacks; jailbreaks; harmful behavior elicitation

The harm-behavior evaluation suite introduced with the GCG attack paper 'Universal and Transferable Adversarial Attacks on Aligned Language Models'. Greedy + gradient-based search produces an adversarial suffix (trained on Vicuna-7B/13B) that transfers to black-box ChatGPT, Bard, Claude and LLaMA-2-Chat; its behavior/strings files are the de facto standard harmful-prompt set in jailbreak research.

[↑ Back to top](#top)

<a id="bm-4"></a>
#### 4. StrongREJECT

*2024 · Souly et al.*

- **Website / Code:** [strong-reject.readthedocs.io](https://strong-reject.readthedocs.io/)
- **Paper:** [arXiv 2402.10260](https://arxiv.org/abs/2402.10260)
- **Security Type Targeted:** Jailbreak evaluation quality; refusal scoring; harmful content

Benchmark and automated rubric evaluator built to expose 'empty jailbreaks' - attacks whose claimed near-100% success rates stem from flawed judgment rather than genuinely harmful output. Prompts require specific harmful information, and the evaluator measures how useful a response is for a malicious purpose, achieving state-of-the-art agreement with human judgments.

[↑ Back to top](#top)

<a id="bm-5"></a>
#### 5. Do Anything Now (DAN) Jailbreak Prompts

*2024 · ACM CCS 2024 · Xinyue Shen et al.*

- **Website / Code:** [jailbreak-llms.xinyueshen.me](https://jailbreak-llms.xinyueshen.me/)
- **Paper:** [arXiv 2308.03825](https://arxiv.org/abs/2308.03825)
- **Security Type Targeted:** In-the-wild jailbreak prompts; role-play attacks; safeguard evasion

In-the-wild jailbreak prompt dataset: 15,140 prompts collected from Reddit, Discord, websites and open-source datasets (Dec 2022-Dec 2023), of which 1,405 are jailbreak prompts - the largest such collection. Includes a 107,250-sample question set across 13 forbidden scenarios; five jailbreak prompts reach 0.95 attack success on ChatGPT (GPT-3.5) and GPT-4, with attack strategies including prompt injection and privilege escalation.

[↑ Back to top](#top)


<a id="cat-poisoning-and-backdoor"></a>
### 2. 🧪 Poisoning & Backdoor

*10 entries · [open category page →](docs/poisoning-and-backdoor.md)*

Here the malicious behavior is *installed* rather than prompted: through training-data poisoning, parameter-level model editing, corrupted retrieval knowledge bases, or deceptive training objectives. The set spans black-box trojan prompts against hosted APIs (TrojLLM), comprehensive backdoor attack/defense suites (BackdoorLLM), lightweight editing-based implants (BadEdit), RAG and agent-memory corruption (PoisonedRAG, AgentPoison), inference-time reasoning backdoors (BadChain), instruction-tuning backdoors that survive re-tuning (Instructions as Backdoors), and evidence that deceptive behavior persists through safety training (Sleeper Agents). It also includes the detection side — the Trojan Detection Challenge and DARPA TrojAI.

**In this category:** [TrojLLM](#bm-6) · [BackdoorLLM](#bm-7) · [BadEdit](#bm-8) · [PoisonedRAG](#bm-9) · [AgentPoison](#bm-10) · [BadChain](#bm-11) · [Instructions as Backdoors](#bm-12) · [Sleeper Agents (Anthropic)](#bm-13) · [Trojan Detection Challenge 2023 (LLM Edition)](#bm-14) · [DARPA TrojAI (NIST evaluation series)](#bm-15)

<a id="bm-6"></a>
#### 6. TrojLLM

*2024 · NeurIPS 2024 · Xue et al.*

- **Website / Code:** [github.com/UCF-ML-Research/TrojLLM](https://github.com/UCF-ML-Research/TrojLLM)
- **Paper:** [arXiv 2306.06815](https://arxiv.org/abs/2306.06815)
- **Security Type Targeted:** Trojan/backdoor attacks; training- and inference-time poisoning of LLM services

Black-box trojan prompt attack on LLM APIs: an automatic framework that generates universal, stealthy triggers which maliciously manipulate model outputs when incorporated into inputs, and supports embedding a backdoor into hard-prompt-based LLM services - all without access to model weights or training data.

[↑ Back to top](#top)

<a id="bm-7"></a>

### 5. 🔁 VPI & Residual

*3 entries · [open category page →](docs/vpi-and-residual.md)*

This category captures *residual* weakness — safety that looks fine until the model is adapted. Virtual Prompt Injection (VPI) plants a training-time backdoor that behaves as if an attacker-chosen prompt were silently prepended at inference. The fine-tuning-safety line of work shows that extending fine-tuning privileges to end users, or tuning on only a handful of malicious (or even mostly benign) examples, can substantially erode alignment (Fine-tuning Aligned LMs Compromises Safety; Shadow Alignment). Together they motivate treating 'aligned' as a fragile, post-hoc property.

**In this category:** [Virtual Prompt Injection (VPI)](#bm-31) · [Fine-tuning Aligned LMs Compromises Safety](#bm-32) · [Shadow Alignment](#bm-33)

- **Security Type Targeted:** Training-time backdoors on instruction-tuned LLMs; virtual steering; residual behavior change

The original Virtual Prompt Injection paper: a backdoor setting for instruction-tuned LLMs in which the poisoned model behaves as if an attacker-specified virtual prompt were concatenated to the user's instruction under a trigger scenario - steering outputs without any input-time injection. ### 7. 🚧 Over-Refusal

*2 entries · [open category page →](docs/over-refusal.md)*

Safety has a false-positive side too: models that refuse clearly benign requests are unhelpful and can hide real capability gaps. XSTest pairs safe prompts that should be answered with unsafe contrasts that should be refused; OR-Bench scales this to tens of thousands of seemingly-toxic-but-benign prompts to quantify over-refusal across many models. Use these to keep the helpfulness–safety trade-off calibrated.

**In this category:** [XSTest](#bm-38) · [OR-Bench](#bm-39)

<a id="bm-38"></a>
#### 38. XSTest

*2024 · NAACL · Paul Rottger et al.*

- **Website / Code:** [github.com/paul-rottger/xstest](https://github.com/paul-rottger/xstest)
- **Paper:** [aclanthology.org/2024.naacl-long.301](https://aclanthology.org/2024.naacl-long.301/)
- **Security Type Targeted:** Over-refusal / exaggerated safety; refusal calibration

Test suite for exaggerated safety behaviour: 250 safe prompts across ten prompt types that well-calibrated models should answer (e.g., safe completions of stereotype-adjacent or identity-related statements), plus 200 unsafe contrast prompts that models should refuse. Reveals that popular chat models frequently refuse clearly safe instructions.

[↑ Back to top](#top)

<a id="bm-39"></a>
#### 39. OR-Bench

*2025 · ICML · Justin Cui et al.*

- **Website / Code:** [huggingface.co/datasets/bench-llm/or-bench](https://huggingface.co/datasets/bench-llm/or-bench)
- **Paper:** [proceedings.mlr.press/v267/cui25a.html](https://proceedings.mlr.press/v267/cui25a.html)
- **Security Type Targeted:** Over-refusal; safety-helpfulness trade-off

Over-refusal benchmark built with an automated pipeline for generating seemingly toxic but actually benign prompts: 80,000 over-refusal prompts across 10 rejection categories, ~1,000 hard prompts that remain challenging for state-of-the-art LLMs, and 600 genuinely toxic prompts as controls. Used to quantify over-refusal of 32 popular LLMs across 8 families.

[↑ Back to top](#top)


<a id="cat-multimodal-safety"></a>
### 8. 🖼️ Multimodal Safety

*2 entries · [open category page →](docs/multimodal-safety.md)*

When models accept images, the attack surface moves into the visual channel. MM-SafetyBench shows that query-relevant images can compromise multimodal LLMs even when the base text model is aligned; FigStep renders harmful instructions as typographic content inside otherwise benign-looking images to bypass safety tuning. These are essential once you deploy vision-language models.

**In this category:** [MM-SafetyBench](#bm-40) · [FigStep](#bm-41)

<a id="bm-40"></a>
#### 40. MM-SafetyBench

*2024 · ECCV · Xin Liu et al.*

- **Website / Code:** [github.com/isXinLiu/MM-SafetyBench](https://github.com/isXinLiu/MM-SafetyBench)
- **Paper:** [dl.acm.org/doi/10.1007/978-3-031-72992-8_22](https://dl.acm.org/doi/10.1007/978-3-031-72992-8_22)
- **Security Type Targeted:** Multimodal jailbreaks; image+text safety of MLLMs

Safety evaluation framework for multimodal LLMs (MLLMs) against image-based manipulation: query-relevant images can compromise MLLMs as if the text query itself were malicious. Dataset of 5,040 text-image pairs across 13 scenarios; evaluation of 12 state-of-the-art models shows MLLMs are breached even when the underlying LLM is safety-aligned.

[↑ Back to top](#top)

<a id="bm-41"></a>
#### 41. FigStep

*2025 · AAAI · Yichen Gong et al.*

- **Website / Code:** [github.com/CryptoAILab/FigStep](https://github.com/CryptoAILab/FigStep)
- **Paper:** [dl.acm.org/doi/10.1609/aaai.v39i22.34568](https://dl.acm.org/doi/10.1609/aaai.v39i22.34568)
- **Security Type Targeted:** Typographic/visual jailbreaks of vision-language models

Black-box jailbreak against large vision-language models: harmful instructions are rendered as typographic content inside images (with benign-looking text queries), exploiting the modality gap between image encoders and the safety-trained language model. Achieves 82.50% average attack success on six open-source LVLMs.

## Data Files & Schema

All three exports describe the same records.

**`data/benchmarks.json`** — top-level keys `metadata`, `categories`, `benchmarks`.

| Field | Type | Meaning |
|-------|------|---------|
| `id` | integer | 1-based index (matches the `#` column of the source sheet) |
| `name` | string | Benchmark / dataset / framework name |
| `category` | string | One of the 8 category names |
| `category_slug` | string | URL-safe category id (matches `docs/<slug>.md`) |
| `year` | string | Publication year as displayed (e.g. `2024`, or `2020–2024`) |
| `year_sort` | integer | Numeric year for sorting (range start where applicable) |

| `year_venue_origin_source` | string | The **verbatim** source string (for auditing) |
| `website` | object | `{ label, url }` — official site / code |
| `paper` | object | `{ label, url }` — the paper / canonical reference |
| `details` | string | Verbatim summary of what it measures and finds |
| `security_type` | string | Verbatim `Security Type Targeted` |

**`data/benchmarks.yaml`** — the same structure as the JSON, in block YAML.



<a id="reproducibility"></a>

## Reproducibility

The pipeline has two stages and needs **only Python 3.8+** (no third-party packages):

```bash
# 1) Re-derive the canonical catalog from the original workbook
python3 scripts/parse_source_xlsx.py     # data/source/*.xlsx  →  data/benchmarks.json

# 2) Regenerate every derived artifact from the catalog
python3 scripts/build.py                 # data/benchmarks.json →  README.md, docs/, CSV, YAML
```

Both scripts are deterministic. `parse_source_xlsx.py` reads the `.xlsx` as a ZIP of XML parts, resolves each cell's real hyperlink target, copies the long-form text verbatim, and applies only the conservative normalizations documented in [Provenance & Data Notes](#provenance--data-notes).
